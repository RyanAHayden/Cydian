# B235 iOS 7 / iOS 13 OLED Black: launch sets of their own

## What changed

- `web/app/core/settings.js`: `STYLE_LAUNCH` (`ios7: { oled: "oled7" }`, `ios13: { oled: "oled13" }`) and
  `launchKey(style, palette)`. The launch set follows the style; the page's `data-palette` stays `oled`.
- `web/app/screens/settings.js` `applyTheme`: the shell's `app.theme` carries `launchKey(style, …)` for
  `darkPalette` and `lightPalette`, so the shell's ground and next splash use the era's set.
- `native/launch/make.py` THEMES: `oled7` (flat #000 bars and ground, #262626 hairline, from ios7.css) and `oled13`
  (the same with iOS 13's #38383a hairline, from ios13.css). No highlight, gloss or shadows. `themes/oled7`,
  `themes/oled13` regenerated by `make.py`; no other theme's files changed.
- `native/launch_check.py` THEME_KEYS, `native/Sources/App.swift` `Launch.ground` (`oled7`, `oled13` → black).
- `native/test_launch_grounds.py`: reads STYLE_LAUNCH's keys as palettes needing a set, and checks both new sets
  against ios7.css / ios13.css dark blocks (the White branch generalised to the eras' flat bars).
- `web/app/screens/settings.test.js`: iOS 7 dark sends `oled7`, iOS 13 `oled13`, the page keeps `data-palette` oled.

## Decisions

- Picked "make the set follow the style" over a new `STYLE_PALETTES` key. A new palette key would change
  `data-palette` on the page, and that touches `THEME_COLORS`, theme-boot.js's tables, the concept tool's theme label
  (it would show "Oled7", not "OLED Black") and many web tests, all for something only the shell needs. ios7.css and
  ios13.css draw their dark theme by `data-style` + `data-theme`, not by `data-palette`. So theme-boot.js is unchanged.
- Two keys, not one: iOS 13's dark hairline is #38383a, not iOS 7's #262626, so one shared set would still be wrong
  for iOS 13. Keys carry a digit, which the helper (`[a-z0-9]`) and `Splash.key` accept.
- iOS 13's White also differs from iOS 7's (#f2f2f7 ground, #f9f9f9 bars) but still opens on `white`. Not in this
  task; filed as a follow-up. `STYLE_LAUNCH` can take it as `ios13: { white: … }`.

## Not verified

- The splash on a device (iPhone 7 jailbreak build, iOS 7 style, dark): this task's brief asks for no phone test,
  and the iPhone 7 is shared with the other slots. The new sets are checked against the CSS by
  `test_launch_grounds.py` and the bundle check (`launch_check`) in the gate's builds.
- An older shell given `oled7`: `Launch.ground` falls back to OLED Black's ground and `Splash.key` finds no set, so
  there's no cover. That's what the code says; not run.
